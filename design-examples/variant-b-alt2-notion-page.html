How we work

Keep it framework-native. One preHandler hook, opt-in per route via config.auth. No wrapper, no hidden state.

This doc is the source of truth for the auth refactor. We'll move JWT verification into a Fastify preHandler so every route can opt-in with a single decorator. Comments are on the right — add inline threads per block.

Goals

  • Typed end-to-end. request.user is available in every handler and log.
  • Zero deps. Use fastify-plugin only — no extra JWT library.
  • 60 req/min per user rate limit in the same hook (keep it colocated).
Implementation steps 3 steps
1Create plugins/auth.ts — decorate request, add preHandler with verifyJwt + in-memory counter.
2Add per-route config: { auth: true } to /me, /billing.
3Cover with tests — 401, 429, and happy path.
plugins/auth.ts TypeScript · Fastify 5
No dependencies 
// Fastify preHandler — opt-in per route
import fp from 'fastify-plugin'
import { verifyJwt } from './jwt'

export default fp(async (app) => {
  app.decorateRequest('user', null)
  // in-memory 60/min per user (swap with Redis later)
  const hits = new Map<string, number[]>()

  app.addHook('preHandler', async (req, reply) => {
    if (!req.routeOptions.config?.auth) return
    const token = req.headers.authorization?.replace('Bearer ', '')
    if (!token) return reply.code(401).send({ error: 'missing token' })
    req.user = await verifyJwt(token)
    // rate limit: 60/min
    const now = Date.now(), arr = (hits.get(req.user.id) ?? []).filter(t => now - t < 60_000)
    if (arr.length >= 60) return reply.code(429).send({ error: 'rate_limited' })
    arr.push(now); hits.set(req.user.id, arr)
  })
})

// usage
app.get('/me', { config: { auth: true } }, async (req) => req.user)
Typed · no new deps · 429 when limited

“Keep the hook colocated. When we outgrow the Map, swap it for Redis without changing the route API.” — Efe, review
